# 文档写作规范

这份规范用于你以后自己写文章，或者让 agent 帮你排版时直接复用。目标是让文章结构统一、摘要统一、图片说明统一、图注视觉统一。

这份规范不是纯学术论文模板，也不是纯博客随笔模板，而是一个适合你这个站点的混合标准：

- 写教程、项目复盘、技术分析时，尽量靠近技术文档写法。
- 写研究型分析、数据报告时，尽量靠近论文摘要和图注写法。
- 写纯个人记录时，可以适当放松，但不要破坏整篇文章的一致性。

## 1. 写作目标

- 让读者一眼看懂这篇文章讲什么。
- 让文章里的标题、摘要、图片、图注、列表有稳定格式。
- 让你和 agent 在排版时有一套可以直接复用的规则。
- 让图片说明既适合博客阅读，也能兼容偏研究型的写法。

## 2. 文章骨架

建议每篇文章按这个顺序组织：

```md
---
title: 文章标题
date: 2026-04-20 12:00:00
lang: zh-CN
slug: English-Slug
description: 摘要：30 字以内的一句话概括
photos:
  - /images/xxx/example.png
---

# 主标题

**摘要：30 字以内的内容概括。**

<!-- more -->

正文内容
```

推荐的逻辑顺序是：

1. 标题
2. slug
3. 摘要
4. 代表性图片或最核心的一张图
5. `<!-- more -->`
6. 背景或结论
7. 方法与过程
8. 图表和结果
9. 结论与下一步

如果是偏记录型文章，可以把“背景”和“过程”合并。  
如果是偏分析型文章，建议先给结论，再给过程。

首页瀑布流的优先策略是：

- `description` 负责一句话摘要
- `photos` 负责封面图
- `<!-- more -->` 负责正文截断

如果文章已经按这套规范排版过，正文里就不要再重复写主标题和摘要，避免首页、正文和图注之间出现重复信息。

不要把首页封面图依赖正文首图来碰运气，优先把封面图写进 front matter 的 `photos`。
`photos` 默认只用于首页卡片展示，不会自动重复塞进正文页。

封面图建议统一按这个标准制作：

- 比例：`3:2`
- 推荐尺寸：`1200 x 800`
- 方向：横版
- 主体：尽量居中
- 安全区：四边尽量留出 `8% ~ 12%` 的空隙
- 文字：尽量少，且不要贴边

这个比例比 `16:9` 更不容易裁掉主体，也比 `4:3` 更适合博客首页卡片。

## 3. 摘要规范

每篇文章开头都应该有一个摘要。

规则：

- 摘要控制在 `30` 个字以内。
- 摘要尽量直接说结论，不要写空话。
- 摘要最好放在主标题下面。
- 如果文章有图片，摘要前后尽量和代表图形成一个整体。
- 摘要必须使用固定格式：`摘要：xxxxxx`。
- `slug` 统一写英文，中文和英文配对文章尽量使用同一个 `slug`。

推荐写法：

```md
**摘要：这篇文章总结了 ChatGPT 安卓端的核心体验和用户需求。**
```

不推荐写法：

- 摘要太长，变成正文第一段。
- 摘要只写“本文做了一个分析”，没有信息量。
- 摘要和正文重复太多，读起来像换行版开头段。
- 摘要前面不要再加其他前缀，比如“本文摘要”“内容摘要”。

## 4. 代表性图片

如果文章里有多张图片，开头建议只选一张最有代表性的图。

选择原则：

- 优先选最能代表文章主题的图片。
- 优先选能让读者一眼理解主题的图片。
- 如果是数据分析文章，优先选结果最有代表性的总览图。
- 如果是项目复盘，优先选最能代表最终成果或关键过程的图。
- 如果没有合适的代表图，可以不放开头图，但摘要仍然要保留。

推荐写法：

```md
photos:
  - /images/feishu-migration/star-home-scam-data-analysis/star_home_excel_source.png
```

这张图如果是文章主视觉，建议放在摘要附近，并且保持图注简短。

如果这张图同时也要在正文中解释，可以在正文里再写一次图片和图注：

```md
![](/images/feishu-migration/star-home-scam-data-analysis/star_home_excel_source.png)
*星星回家互助档案 Excel 数据源*
```

## 5. 图片与图注

如果图片后面需要跟稳定的图注，最推荐用 `figure` 写法：

```md
<figure class="post-figure">
  <img src="/images/xxx/example.png" alt="">
  <figcaption>这是一句简短的图注</figcaption>
</figure>
```

规则：

- 图片单独占一行。
- `figure` 里的 `img` 统一写成空 `alt`，不要在里面补说明文字。
- `figcaption` 负责图注，图注尽量短，最好是一句说明，不写太长的段落。
- `figcaption` 不加编号，除非整篇文章本身就是学术式编号体系。
- 封面图也按同样原则处理，优先用专门制作的 `3:2` 图片，而不是让正文图临时充当封面。

视觉规范：

- 居中对齐。
- 颜色用浅灰。
- 字号比正文小一档。
- 图注和图片的间距要紧凑，但不能贴得太死。
- 图注长度控制在 1 行到 2 行内，避免把版面撑散。

如果你写的是更偏研究报告的文章，也可以把图注写得更完整一点：

```md
<figure class="post-figure">
  <img src="/images/xxx/example.png" alt="">
  <figcaption>图 1. 用户地域分布结果，数据来自公开表格样本。</figcaption>
</figure>
```

这种写法更接近研究型写作，适合数据分析、实验总结、方法报告。

## 6. 通用写作标准

### 6.1 标题

- 中英文标题都要具体，直接告诉读者这篇文章在讲什么。
- 英文标题尽量用 sentence case。
- 一级标题只出现一次，不要重复堆同级标题。
- 不要为了排版而用标题代替正文强调。

### 6.2 结构

- 先给结论或摘要，再给过程。
- 过程部分按逻辑分小节，不要一大段到底。
- 如果是教程，标题最好是任务导向。
- 如果是概念介绍，标题最好是名词短语。

### 6.3 列表

- 列表项尽量平行，句式保持一致。
- 列表不要太长，能拆成小节就拆。
- 顺序重要就用编号列表，不重要就用无序列表。
- 只有一个条目时不要硬写成列表。

### 6.4 表格

- 只有当一项内容有两个及以上属性时再用表格。
- 表格之前先给一句引导，不要直接硬上表格。
- 表头要清楚、短、平行。
- 如果只是单纯罗列项目，更适合用列表。

### 6.5 研究型文章

如果你写的是更接近研究、实验、数据分析的文章，建议按这个顺序组织：

1. 标题
2. 作者与摘要
3. 背景或问题定义
4. 方法
5. 结果
6. 讨论
7. 结论
8. 参考资料

这种结构更接近正式研究写作，适合数据分析、方法比较、实验记录和长篇项目复盘。

## 7. 翻译稿规则

如果文章是 AI 翻译成其他语言的版本，翻译提示必须放在 `<!-- more -->` 后面。
翻译提示还必须写明翻译模型和时间，统一使用同一种句式，方便后续维护和批量检查。

目的：

- 让首页摘要区保持干净。
- 让翻译说明只出现在正文区域。
- 让读者先看到文章主体，再看到翻译来源说明。

推荐写法：

```md
---
title: Hello World
lang: en
description: "Summary: A short summary in under 30 words."
photos:
  - /images/xxx/example.png
---

# Hello World

**摘要：30 字以内的内容概括。**

<!-- more -->

> Translation note: This English version was translated by Codex (GPT-5) on 2026-04-20 18:01:46 CST. The source text is the corresponding Chinese post in this repository.

正文内容
```

规则：

- 翻译提示不要放在文章最开头。
- 翻译提示建议用引用块，和正文视觉上分开。
- 翻译提示必须说明模型、来源、时间，不要写太长。
- 如果文章是人工原创英文稿，就不需要这个提示。
- 如果是英文翻译稿，建议所有篇目统一使用同一种翻译备注句式。

## 8. 不推荐的写法

- 图片和图注之间空一整段。
- 图注写成普通正文段落，导致样式不统一。
- 图注过长，写成说明小论文。
- 在 `![](...)` 里塞说明文字，把图片语法当成注释区。
- 一张图下面再套多层列表，会让排版很乱。
- 标题只写“记录一下”“一些想法”，但正文又很长。
- 一个列表里每一项句式完全不同，读起来像拼接。
- 表格没有说明就直接出现，读者不知道该看什么。
- 摘要太长，直接替代了正文第一段。
- 已经有 front matter `description` 和开头排版时，正文还重复写标题和摘要。
- 翻译提示放在文章最顶部，打断首页阅读。
- 翻译提示没有写明模型和时间，导致不同英文稿格式不统一。

## 9. 给 agent 的排版要求

如果以后让 agent 帮你排版，可以直接照这个要求说：

- 每篇文章都要有一个 30 字以内的摘要。
- 如果已经在 front matter 里写了 `description`，并且正文开头已经做过一次规范排版，就不要再在正文里重复写标题和摘要。
- 如果有图片，优先选择一张最有代表性的图片放在开头。
- 有图注时优先使用 `figure` + `figcaption`。
- 纯插图时再使用 Markdown 原生图片语法。
- 图注必须居中、灰色、小字号、贴近图片。
- 图注内容尽量简短，不要改写成正文。
- 如果是翻译稿，翻译提示放在 `<!-- more -->` 后面，并写明模型和时间。
- 遇到多张图时，保持同一篇文章的图注风格一致。

## 10. 适用范围

这套规范主要适用于：

- 数据分析文章
- 项目复盘文章
- 教程文章
- 带图的个人记录
- AI 翻译稿

如果是纯文字随笔，可以适度放宽，不必强求每张图都写图注。
